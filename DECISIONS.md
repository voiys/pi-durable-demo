# Decisions

- 2026-10-18 · Tools pinned with mise (`mise.toml`): node 24.20.0, pnpm 12.6.0 (the versions already installed and working on this machine). Asked for by the user.
- 2026-10-18 · No Cloudflare login for v0: alchemy v2 local dev falls back to a dummy account id when none is configured (`alchemy-v2-beta83: packages/alchemy/src/Cloudflare/LocalAccount.ts`), and nothing in v0 needs a remote resource.
- 2026-10-18 · Auth model (user's call): users sign in with email/password (better-auth). "Sign in with ChatGPT" is a separate *connect your ChatGPT plan* step, and pi runs on that plan's token. One ChatGPT account may be connected to several app users for the demo. No backup model: a user with no connected plan can't chat, and the app says so.
- 2026-10-18 · SIWC terms (https://openai.com/policies/sign-in-with-chatgpt-terms/, dated 2026-09-29) limit the demo: tokens may only be stored "local and under the user's control", requests must come from the user's own runtime, and "using one user's subscription to fulfill another user's requests" is banned. So: the app stays local-only (workerd on this machine). One ChatGPT plan connected to several app users is OK only because every one of those test users is the same person (the owner). It must never be used by other people, and the app is not deployed with SIWC.
- 2026-10-18 · (Superseded 2026-10-19 by bots) OptChat is the default (and only) chat structure: every chat's main agent runs on the OptChat memory (user's call: "we should use optchat as our default chat structure"). The per-chat "OptChat" button and `optchat` kv flag go away. Subagents keep plain pi context.
- 2026-10-18 · Model picker offers only GPT-6.1 Sol, GPT-6 Astra and GPT-6 Luna (user's pick), filtered by what the ChatGPT plan lists.
- 2026-10-18 · (Superseded 2026-10-19: memory is per bot) OptChat memory is per user (User DO), shared by every chat; log entries carry the chat id in metadata; the `[chat "<title>"]` label is added only where a model reads the text (compactor source, zoom), never stored (user's call). Old per-chat memories were dropped, not migrated (local dev data). Deleting a chat keeps its lines in the memory: the log is append-only by design.
- 2026-10-18 · OptChat fix plan (research/optchat-fix-plan.md) applied: pi compaction is declined for root conversations (OptChat owns history, upstream index.ts:475); each chat's memory cursor (last logged entry id) lives in the User DO (now: in each Bot DO's kv); logging happens at run start (settled, then input), after each tool round and at the answer; one view per run (memo); the summarizer is gpt-6-luna at low effort, 3 at a time, 90 s timeout, and it fails loudly if the plan lacks it.
- 2026-10-19 · Bots replace chats (user's call, modeled on the Grok Bot app): the rail lists bots, each bot is one endless conversation (one Bot DO, name `<userId>--<botId>`) with its own OptChat memory, as the OptChat recipe intends ("one endless chat"). No chat list, no draft flow, no new-chat button. Old chats, search index and memories were wiped, not migrated; the ChatGPT connection and test logins were kept.
- 2026-10-19 · Memory scope: per bot only. A bot remembers everything that reaches its conversation (the user, its subagents' reports, other bots' messages, its routines firing, later group chats it joins). The User DO keeps the bot catalog, search across all bots and the ChatGPT connection; there is no shared user memory. Bots reach each other by name with the `bots` tool (names unique per user, case-insensitive).
- 2026-10-19 · A bot has a name and instructions (its prompt section, main agent only), kept in the User DO and pushed to the Bot DO's kv because pi renders sections synchronously. Avatar = a palette color + initial, assigned on create.
- 2026-10-19 · Routines: cron prompts per bot on the agents SDK `Scheduler` capability (Lifecycle), stored in the Bot DO, created by the bot's `routines` tool (or later the UI), toggled/deleted in the details panel. Cron is UTC. A routine firing arrives in the conversation as `[routine "<name>"] <prompt>`, logged to memory as work.
- 2026-10-19 · Per-bot storage for research (research/bot-storage.md): AI Search is remote-only (needs a Cloudflare account) and D1 can't be bound at runtime, so the first store will be a `sql` tool over the Bot DO's own SQLite (FTS5 + window functions work locally). AI Search per bot (namespace binding, one instance per bot) comes when we have an account. DuckDB skipped for now (ducklings works on Workers but adds little at this size, 128 MB cap).
- 2026-10-19 · Web research runs locally: SearXNG (Docker, `searxng/searxng:2026.10.4-d48c4b555`, declared in alchemy.run.ts, JSON API on 127.0.0.1:8888) behind a `web_search` tool, and a `web_fetch` tool that reads a page as text with numbered links (HTMLRewriter). Replaces AI Search until there's a Cloudflare account (user's call).
- 2026-10-19 · Each bot gets a `BotData` DO (same name as its Bot DO): a SQLite the bot runs any SQL on (`sql` tool: build tables from what it reads, analyze, temp data) and a library of markdown reports (`library` tool), shown in its details panel. Separate DO so a bot's SQL can never touch pi's or OptChat's tables. DuckDB skipped (research/bot-storage.md).
- 2026-10-19 · Main bot (user's call): one per user, the first bot until the user picks another in the details panel. Only its conversation gets the `fleet` tool (create, rename, re-instruct, delete bots in natural language), toggled per conversation with pi `configure({ extensions })`. The main bot can't be deleted.
- 2026-10-19 · Group chats (user's call): a Group DO per room holds only the transcript (agent state). The user's message reaches every member (or only the @mentioned ones); a bot's message reaches only the bots it @mentions, at most 6 bot posts per user message. Each member answers in its own group conversation inside its Bot DO (not its DM), replies PASS to stay silent, and logs the room into its own memory. Disbanding deletes the room only. A bot in a group can't be deleted until the group is disbanded.
- 2026-10-19 · UI is iMessage-like (user's call): bot rail (main bot on top), blue/gray bubbles, time dividers, other bots as group-chat senders, one plain-words activity line per reply (steps on expand, never raw arguments or SQL), report cards. Primary color is iMessage blue darkened to hsl(211 100% 45%) so white bubble text passes 4.5:1 (research/ui-review-2026-10-19.md).
