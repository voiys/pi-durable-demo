# Decisions

What the demo settled on and why. Dates are when it was decided; superseded calls are gone (see git history).

- 2026-10-18 · Tools pinned with mise (`mise.toml`): node 24.20.0, pnpm 12.6.0.
- 2026-10-18 · No Cloudflare account: alchemy v2 local dev falls back to a dummy account id when none is configured (`alchemy-v2-beta83: packages/alchemy/src/Cloudflare/LocalAccount.ts`), state is `Alchemy.localState()`, and nothing needs a remote resource.
- 2026-10-18 · Auth: users sign in with email/password (better-auth). "Sign in with ChatGPT" is a separate *connect your ChatGPT plan* step, and pi runs on that plan's token. No backup model: a user with no connected plan can't chat, and the app says so.
- 2026-10-18 · SIWC terms (https://openai.com/policies/sign-in-with-chatgpt-terms/, dated 2026-09-29): tokens may only be stored "local and under the user's control", requests must come from the user's own runtime, and "using one user's subscription to fulfill another user's requests" is banned. So the app runs locally only (workerd on your machine), each person connects their own plan, and it is never deployed with SIWC.
- 2026-10-18 · OptChat (Victor Taelin's design, port of jonaslsaa/pi-optchat) is each bot's memory: one endless conversation whose log is folded into a tree of summaries, with a fixed-size view per turn plus `zoom`, `search` and `date` tools. pi's own compaction is declined for the main conversation (OptChat owns history, upstream index.ts:475). Logging happens at run start (settled, then input), after each tool round and at the answer; one view per run. The summarizer is gpt-6-luna at low effort, 3 at a time, 90 s timeout, and it fails loudly if the plan lacks it.
- 2026-10-19 · Bots, not chats (modeled on the Grok Bot app): the rail lists bots, each bot is one endless conversation in its own Bot DO (name `<userId>--<botId>`) with its own OptChat memory. A bot remembers everything that reaches it: you, its subagents' reports, other bots, its routines, the groups it's in. There is no shared user memory. The User DO keeps the bot catalog, search across all bots and the ChatGPT connection.
- 2026-10-19 · A bot has a name, instructions (its prompt section, main agent only) and a look (bloub shape, color, face). Every bot runs gpt-6.1-sol at low reasoning; there is no model picker.
- 2026-10-19 · Bots reach each other by name with the `bots` tool (names unique per user, case-insensitive).
- 2026-10-19 · Main bot: one per user, the first bot until you pick another in its details. Only its conversation gets the `fleet` tool (create, rename, re-instruct, delete bots in plain words), toggled per conversation with pi `configure({ extensions })`. The main bot can't be deleted.
- 2026-10-19 · Routines: cron prompts per bot on the agents SDK `Scheduler`, stored in the Bot DO, created by the bot's `routines` tool, toggled and deleted in its details. Cron is UTC. A routine firing arrives as `[routine "<name>"] <prompt>` and is logged to memory as work.
- 2026-10-19 · Research runs locally: SearXNG in Docker (`searxng/searxng:2026.10.4-d48c4b555`, declared in alchemy.run.ts, JSON API on 127.0.0.1:8888) behind a `web_search` tool, and `web_fetch`, which reads a page as text with numbered links (HTMLRewriter). Cloudflare AI Search would replace both once there's an account (research/bot-storage.md).
- 2026-10-19 · Each bot gets a BotData DO (same name as its Bot DO): a SQLite the bot runs any SQL on (`sql` tool) and a library of markdown reports (`library` tool), both shown in its details. A separate DO so a bot's SQL can never touch pi's or OptChat's tables. DuckDB skipped (research/bot-storage.md).
- 2026-10-19 · Group chats: a Group DO per room holds the transcript and the room's purpose ("What it's for"), which every member reads as part of its instructions. Each member answers in its own group conversation inside its Bot DO, replies PASS to stay silent, and logs the room into its own memory. Every member sees the whole room: each delivery carries what was said since that bot last heard from it (`heard:<botId>` in the Group DO); @mentions only decide who is asked to answer, at most 6 bot posts per user message. Disbanding deletes the room. A bot in a group can't be deleted until the group is disbanded.
- 2026-10-19 · Group routines: a routine made inside a group belongs to it. When it fires the bot shows as typing in the room, works in its group conversation and its answer is posted like any reply. In a group the routines tool lists and removes only that room's routines; the group's details list them with on/off switches. Disbanding removes them. Local dev runs with `TZ=UTC` because the agents scheduler parses cron in the runtime's local time (cron-schedule `getHours`), which is UTC on Cloudflare but the host's zone under local workerd.
- 2026-10-19 · UI is iMessage-like: bot rail (main bot on top), blue/gray bubbles, time dividers, other bots as group senders, one plain-words line per tool call (its intent and outcome, never tool names, arguments or SQL), report cards, replies and quotes, questions as cards. Primary is iMessage blue darkened to hsl(211 100% 45%) so white bubble text passes 4.5:1. DESIGN.md and research/ui-decisions.md hold the details.
