## 2. OptChat (PRIMARY SOURCE EXISTS)
Author: Victor Taelin (@VictorTaelin). Not a product by Mario/Earendil.
- Tweet https://x.com/VictorTaelin/status/2106569004454219875 (2026-10-04): "I can't overstate how excited I am about OptChat." Recipe gist: https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449 (reply 2106575078838178270).
- Definition, gist first published rev f51fe5c9 (raw URL in thread.txt, saved raw/v1/optchat-orig.md lines 1-25): "the chat history itself is the memory, stored as a compressed tree." ONE endless chat; every message logged verbatim forever; background cheap model compresses log into binary tree of one-line summaries; each user message starts a FRESH call seeing a fixed-size "view" (~64k tokens, recent fine, old coarse); agent can "zoom" a line into the two it was made from, down to the original. No context rot, no manual /compact.
- Current gist revision (2026-10-08) renamed the body to "UniiChat"; description still "OptChat". Cache bug fix in rev of Oct 8 (tweet 2108014611807277535, via grok; unverified by me).
- Subagents section 9 (optchat-orig.md:694-730): optional. `spawn(tasks)` parallel subagents, first message = view at spawn time; subagents get zoom+date, not spawn; their tool calls stay out of main log; reports arrive as ONE message `"[id] report"` logged as kind user (compactor tags `work:`); `tell(id, message)` reaches a running subagent between tool calls; "Serve these tools from the harness process (e.g. MCP over HTTP...)". => "one main by design" = David's meaning: a single unified main agent whose chat is the memory, subagents only report back.
- Implementations (all independent): kevinqz/optchat-durable (v0.5.0 per README, Pi Durable ext; pinned ctx `optchat-durable` @6b2285c; src/extension.ts defines defineExtension name "optchat" with memory tools zoom/date/search, tasks, GenerationTask beforeRequest hook), jonaslsaa/pi-optchat (npm pi-optchat 0.8.6, 270 stars, "independent Pi implementation, not Victor's official"), ericjuta/omp-optchat, gebeer/shitty-optchat, fourseven/hermes-optchat, 96Ems/opencode2-plugin-optchat, ahlner/opencode-optchat, @ahayter/pi-optchat-rs 0.4.0, jeffton/batty. (Descriptions from grok; only the first three/four READMEs read by me.)

## 4. HOW TO MAKE CUSTOM TOOLS FOR PI DURABLE (user's side question; verified in source)
Source: pi repo tag v1.3.0 (ctx `pi-source-v1.3.0`, commit 71023aec) packages/durable. npm @earendil-works/pi-durable latest 1.3.0 (versions list incl 1.2.0, which pi-durable-cloudflare pins).
- README.md "Tools" (~l.171-200): `defineTool({name, description, parameters: Type.Object(...) /*TypeBox from @earendil-works/pi-ai*/, replay:"safe"|"unsafe", execute:async(args, api, context)=>({output:[{type:"text",text}], details, structuredOutput, control}) })`; bundle with `defineExtension({name, tools, tasks, sections, hooks, wraps})`, `registry.install(ext)` BEFORE Harness.open (README "Extensions", l.131-160).
- Tool api: api.commit(tx=>...) for atomic state; api.snapshot(Doc, convId); api.conversation(id) -> {submit({type:"input",content,whenBusy:"steer"|"followUp"|"reject",requestId}), abort(), waitForIdle}; submission.wait() -> {status, answer: EntryId}; api.details({conversationId}) lets UI attach; api.taskId stable across reruns for requestId idempotency.
- Subagent patterns: foreground test/examples/22-subagent-foreground.ts and README.md:538-577; BACKGROUND persistent named subagents test/examples/23-subagent-background.ts (363 lines): Anchor task (background, owns child conversation), Reporter task (delivers message, waits, posts "[subagent X answered...]" to parent as followUp with requestId `subagent-report:${id}`), doc `app.subagents` mapping names->conversation ids (defineDoc scope "conversation"), single `subagent` tool actions spawn/send/stop/status, `replay:"unsafe"`, child gets `configure(tx, child.id,{extensions:{remove:[SubagentTools]}, instructions})`.
- Same pattern live in pi-durable-cloudflare src/search.ts:147-215 (searchHistoryTool, replay safe, child owned by api.taskId) -> ctx `pi-durable-cloudflare` @dcb56ce.
- Announcement https://earendil.com/posts/pi-durable/ : "Pi Durable has no built-in subagents, but they take a few lines of code to build" (announce.txt).
- Gap list for Mario's model (inferred): add `list` (scanConversations / the doc), `inspect`/get-last-message (scanEntries or snapshot last AssistantEntry of target conv), `report` (child -> parent submit followUp from inside child's tool; parent id known via doc), cross-session = tool that calls another Session Durable Object (env.SESSIONS.getByName(id)) RPC and submits to its root conversation; needs a session registry per user (D1/DO) and user-scoped authorization (David noted "access rules inconsistent").
